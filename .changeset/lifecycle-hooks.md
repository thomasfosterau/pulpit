Add the lifecycle hook seam (pulpit#45): composable before / after side effects on every write, per leaf type.

- `./subtype`: `SubtypeDefinition.hooks` takes an `Effect` of `LifecycleHooks` (so an application provides them from a `Context` service / `Layer`; the default is none). **Before hooks** (`BeforeWriteHook`) run inside `create`, `update`, `restore`, `delete` and `restoreVersion`, after the gate and the head read and before the append, in the caller's transaction; each is shown the type, action, node, prior head, patch and viewer (`BeforeWriteEvent`), returns the patch to apply, and may refuse the write with the new `WriteRejected`, appending nothing. **After hooks** (`AfterWriteHook`) run in `subtypeHandlers` once its `transact` returns, are shown the committed `{ id, version }` and the re-read resource (`AfterWriteEvent`), and never fail the write: a failure is logged, or with `afterFailure: "defect"` surfaces as a defect. Hooks run in array order; `composeHooks` concatenates sets and `noHooks()` is the empty one. The cache write-through is now the first after hook (`cacheWriteThrough`), behaviour unchanged. `SubtypeOps` gains `type` and `hooks`, every write's error channel gains `WriteRejected`, and `subtypeHandlers` gains `restore`.
- `./version-chain`: `defineVersionChain(type, store, hooks?)` takes `ChainHooks.beforeAppend`, shown a `ChainAppendEvent` (`WriteAction`, the head the append extends, the patch); the expected-version check still runs against that head after it.
- `./documents`: **breaking** — `DocumentStore.put` returns `DocumentPut` (`{ hash, inserted }`) instead of the bare hash, and `onDocumentInsert(store, hook)` runs a hook after a `put` that inserted (a `DocumentInserted` event), never after a no-op. `makeInMemoryDocumentStore`'s `put` follows.
- `./publication`: `duePublications(since, now, column?)`, the `(since, now]` window of arrived publication stamps as a list filter, for an application's cron: a write's events fire when it is made, never when a future stamp arrives.
