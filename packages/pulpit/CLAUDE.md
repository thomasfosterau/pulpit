# packages/pulpit — `@thomasfosterau/pulpit`

The versioned-content kernel: the only published package in this repo.

## Boundary

- Import only `effect` and `@thomasfosterau/effect-jsonapi`, both peers. Never import Drizzle, a framework or `node:*`: `./registry` and `./content` load in the browser, and the stores are the application's. Nothing from this workspace either (`.fallowrc.json` zone `pulpit`, no outbound rule).
- **Seams before dependencies.** The kernel is written against explicit seam interfaces (the version-chain store, the read scope, the handlers config, the `serveable` hook) because the packages that will fill them were not published when it was written. As of 2026-10-08: effect-jsonapi's server skeleton (`ResourceHandlers`, `Assemble`, `ServerErrors`, `Negotiation`, `Registry`, `Group.flat`, `FlatQuery`) has shipped (exported since 0.15.0; pulpit's peer is `>=0.16.0`), so the handlers seam can be wired (pulpit#5); effect-auth's read scope is on its `trunk` but unpublished (release PR effect-auth#177); effect-drizzle-ext is unpublished; and the resource cache has no planned library (effect-web dropped its Cloudflare package on effect-web#33), so the application fills that seam. Never vendor code from an unpublished package to fill a seam: write against the interface, state its expected shape in [README.md → Seams](README.md#seams), keep the in-memory fakes under `tests/` as its reference semantics, and stop-and-report where a real dependency is needed. The real implementation is a follow-up once its package publishes.

## Invariants

The IDs below are defined in the root [SECURITY.md → Invariant IDs](../../SECURITY.md#invariant-ids).

- **The version chain is append-only** (`VERSION-CHAIN-001/002`). Every write lands at `N_max + 1`; no version row is ever rewritten, deleted or reordered. A restore is a new version whose content came from history, and the only write over a tombstone is the explicit `restore` / `restoreVersion` (`VERSION-CHAIN-006`).
- **A stored document is never rewritten** (`DOC-001`). A `DocumentStore`'s `put` writes only an unseen hash and never updates a stored row; a changed document is a new hash. Hashing is the store's job, to the contract in [README.md → Seams](README.md#seams); the in-memory fake in `tests/in-memory-documents.ts` implements it and is pinned to hashes taken from Postgres, so change the two together.
- **An expected version is checked against the head the append extends** (`appendNext` in `./version-chain`), never against a separate earlier read. The append lands at that head + 1, so the store's `(id, version)` key turns a race lost after the check into `VersionConflict`. That key is what makes `StaleVersion` atomic; don't add a second head read between the check and the append.
- **Update inputs are tri-state**: a value sets, `null` clears a nullable column, `undefined` carries forward. Declare it on the `Resource.make` descriptor; never spell `input.x ?? null`, which turns a carry-forward into a clear.
- **A read never reveals a hidden row** (`SEC-AUTH-ENUM-001`): `get` fails `NodeNotFound`, never `Forbidden`, and `getMany` / `list` omit the row, because a 403 would confirm it exists. The write and history gate (`requireWriter`) answers `Forbidden` for an existing owned row the caller doesn't own, which does confirm existence (owner decision on pulpit#24). Don't extend that behaviour to a read. On a reference leaf the write and history operations hide a row as `get` does (pulpit#101): `defineSubtype`'s `writer` runs `visibleRow`, the check `get` runs, after the rung; never give them a second copy of it.
- **The owned list filter and `canViewOwned` never disagree**, and neither do `defineSubtype`'s `get` / `getMany` and its `list`: the row predicate fails closed exactly where the filter does (a `draft` that isn't exactly `false`, a reference `visibility` that isn't exactly `public`, a declared column the view lacks). The declared-column check, the reading of an owned row's facts (owner, visibility, draft) and the predicate over them are one function each, `declaresColumns`, `ownedFacts` and `canViewOwnedRow` in `src/internal/owned-columns.ts`, which `./subtype` and `./edges` share (`canViewOwned` is `canViewOwnedRow` with a present owner); never re-spell any of them in a module. An owner column holding no string reads as no owner, never as its `String` form: it skips the owner arm and the follower seam (pulpit#85). `tests/subtype.test.ts` checks every row × viewer, both directly and through the factory, and `tests/edges.test.ts` the same facts at an endpoint; change one, change both.
- **An edge is readable only if every end is** (`EDGE-001`). `./edges` checks each end's node by its leaf's own access, hides an edge whose end is missing or hidden, or tombstoned (below the view-deleted rung, which reads a tombstone by its access rule, pulpit#93), and answers `get` with `EdgeNotFound` and `list` by omission, never `Forbidden`. A create's answer never tells a hidden edge from a readable one: `maxEdges` counts only readable edges with live ends, and a collision is `EdgeConflict` either way. `endpointFilter` and `canViewEndpoint` are one rule in two readings, and `tests/edges.test.ts` checks every endpoint state × viewer; change one, change both. A create checks its ends before the write gate, so a 403 never confirms a node.
- **An edge is not a version-chain row.** Its delete is a hard `DELETE` and there is no update, which `VERSION-CHAIN-001/002` permit because they govern a node's versions and an edge has none. Never give an edge a `version` or tombstone column, and never let an edge write touch a chain; tombstoning a node hides its edges and deletes none.
- **Nothing owned-private is ever cache-serveable** (`CACHE-AUTH-005`). `isPubliclyServeable` in `./publication` is the one place pulpit spells the rule; every axis it checks is one the operation layer gates on. effect-auth's unpublished `Cacheability.publiclyServeable` is a second spelling that must converge with it (see SECURITY.md's `CACHE-AUTH-005` row).
- **Declare a registry entry's parent with `parent("key")`, never `Option.some("key")`.** `Option.some` widens the literal to `string` even under `as const`, and every `PickChildren` derivation silently goes empty.
- **A registry violation is thrown at import** (`RegistryDeclarationError`), never an Effect failure: no runtime exists when a registry is declared. A malformed edge family is thrown the same way, by `defineEdgeOps` (`EdgeDeclarationError`).
- **`ownerRef`'s `owner` is a `Relationship.one`**, which effect-jsonapi lists as **required** in the generated `createPayload`. The operation layer stamps the owner from the viewer, so a handler serving the generated payload strips the linkage. `tests/content.test.ts` pins this, so the day effect-jsonapi ships a read-only linkage descriptor is visible (effect-jsonapi#172 closed without one; 0.16.3 has none).

## Terms

- **Node** — a stable identity (`id`) with an append-only chain of versions. The apps spell it `core.node` + `core.node_version`; the kernel knows only the shape.
- **Version chain** — the `(version, action, timestamp)` rows a node accumulates. `action` is `create` (version 0), `update` (an appended version, a restore included) or `delete` (a tombstone that still carries the leaf columns forward).
- **Document** — a content-addressed JSON value (a ProseKit tree, in the apps) stored once by its hash; a version row carries the hash (`documentRef`), never a copy. Its type and schema are the application's.
- **Edge** — a relation between nodes stored as a row of its own (an id, a `createdAt`, one column per end, its qualifiers), outside both nodes' tables. Not a node: no version chain, hard-deleted, never updated. An **end** is one of its node columns, declared with the endpoint leaf's access and view and an optional `maxEdges` (the cardinality limit at that end). A taxonomy is a reference leaf plus an edge family; the kernel has no category or tag vocabulary.
- **Leaf** — a concrete subtype (a post, a garden, an image): its own version table keyed `(id, version)` and its current-version view.
- **Content axes** — `visibility` (`public | followers | private`) and the binary `draft` flag, both on the Content branch's version row; a tombstone is the third, orthogonal axis.
- **Registry** — an application's ordered list of `RegistryEntry` (marker levels without a resource, leaves with one). The kernel owns the flag vocabulary and `validateRegistry`; the tree is the application's.
- **Store** — a seam implementation that persists and applies no policy (`VersionChainStore`, `LeafStore`, `DocumentStore`, `EdgeStore`). Policy is the kernel's; persistence is the store's.
- **List filter** — a read predicate as data (`ListFilter`), rendered to SQL by a store and evaluated in memory by the fakes.
- **Access kind** — `reference` (corpus material written at the corpus-write rung, readable below the view-private rung only where the view has no `visibility` column or the row's is `public`) or `owned` (a member's own row, `owner_id` + `visibility`, gated per viewer). Mirrors the registry's `referenceData` ⊕ `owned` flags.
