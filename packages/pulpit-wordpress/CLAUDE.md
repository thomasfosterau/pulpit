# packages/pulpit-wordpress — `@thomasfosterau/pulpit-wordpress`

The WordPress-compatible (`wp/v2`), read-only REST API over the kernel's chains: the second package in this repo. It exports the read API (`./api`, pulpit#86 phases 1 and 2: posts, pages, media, categories, tags, authors and the discovery index), its `effect/http` adapter (`./http`), the `IdCodec` seam (`./ids`, pulpit#114) and its in-memory fake (`./testing`); `src/internal/wire.ts` holds WordPress's own wire vocabulary (the error envelope, dates, `Link`, `_fields`), off docgen. It is `"private": true` until the owner sets up its publishing ([PUBLISHING.md](../../PUBLISHING.md)). The spec, and the owner's decisions on it, are on pulpit#86; read them before adding code.

## Boundary

- **Import only `effect` and `@thomasfosterau/pulpit`, both peers.** Add `@thomasfosterau/effect-jsonapi` as a peer only if the adapter imports it itself. Never import Drizzle, a framework, an HTML renderer or `node:*`. Rendering a document to HTML is an app-filled `render` seam (pulpit#86, decision 3), and integer ids are an app-filled `IdCodec` seam (pulpit#114).
- **Import the kernel by its name and through its exports only** (`@thomasfosterau/pulpit`, `@thomasfosterau/pulpit/subtype`, …), never by a relative path into `packages/pulpit`. This holds for `tests/` as well as `src/`. Fallow checks it in two layers, but only through the local PreToolUse hook on `git commit` / `git push` (AGENTS.md → Agent sessions); CI doesn't run fallow.
  - The rule-pack rule `pulpit/adapter-imports-kernel-by-name` (`fallow-rules.json`) bans the canonical relative spellings from any file in this package: a static `import` or re-export whose specifier starts with `../pulpit` … `../../../../pulpit` or `../../packages/pulpit` … `../../../../../packages/pulpit`. It matches the raw specifier by path segment (no globs, no normalisation), so it misses a dynamic `import(…)` and a non-normalised path such as `./../../pulpit/…`, `../src/../../pulpit/…` or `../../pulpit-wordpress/../pulpit/…`; don't write those. The boundary zones can't do this: a zone matches the file an import resolves to, and `@thomasfosterau/pulpit/filter` resolves to the same `packages/pulpit/src/filter.ts` as `../../pulpit/src/filter.ts`.
  - The kernel's `src/internal/` and `tests/` are the `.fallowrc.json` zone `pulpit-internal`, which this package's zone may not import, so even a package-name import can't reach them. The kernel's in-memory fakes are the public `./testing` export (pulpit#127, landed in pulpit#135): this package's tests import them as `@thomasfosterau/pulpit/testing`, never by a path into the kernel. `packages/pulpit/src/testing.ts` is in the `pulpit` zone, which this zone may import.

  In `src/`, `build` also rejects a relative import into the kernel: it escapes `tsconfig.build.json`'s `rootDir` (TS6059). The type check (`tsconfig.json`) covers `tests/` with no `rootDir`, so it accepts one there; in `tests/` the fallow rule is the only guard.

- **The kernel never imports this package.** The `pulpit` zone's only allowed target is `pulpit-internal`.
- **Reuse the kernel's read gates; never re-spell them.** Reads go through `SubtypeOps.get` / `getMany` / `list` / `owners` (and `readableOwners` across them), and `EdgeOps.list` / `memberFilter` / `nonMemberFilter` / `countBy`, so `SEC-AUTH-ENUM-001` and `EDGE-001` hold by construction. If the adapter needs something the kernel doesn't export, that is a kernel issue (as pulpit#112 and pulpit#113 are), not a copy here.
- **Ids decode before the read gate and encode after it** (`SEC-AUTH-ENUM-001`). Every wire id goes through `./ids` (`integerIds` or `stringIds`), and a wire id that decodes to none (unknown to the codec, or no WordPress id at all) answers exactly as a hidden row does: `404`, never a `400` or a `500`. Encode only a node the read gate has let through, once per response, never per item (`PERF-DB-001`).
- **The adapter's fakes are its public `./testing`** (`src/testing.ts`), mirroring the kernel's: the reference semantics of each seam in [README.md → Seams](README.md#seams), imported by this package's tests and an application's. It is not on the root barrel, and nothing in `src/` but `testing.ts` itself imports it; change a seam's contract and its fake together.
- **No application vocabulary.** `post`, `page`, `attachment`, `category` and `tag` are WordPress's protocol vocabulary; the application binds its own leaves to them.

## In-repo wiring

- It depends on the kernel as `workspace:*` (a devDependency) and peers on it as `workspace:^`, which `pnpm publish` rewrites to `^<the kernel's version>`. Before 1.0 that range excludes the kernel's next minor, so a kernel minor release gives this package a patch release with the new range (Changesets v3 bumps a dependent whose peer range the new version leaves).
- Its tasks are the kernel's, from the root `vite.package.ts`. Its `check` is in the root `check` task, and `tests/dist-consumer/src/wordpress.ts` type-checks its emitted declarations.
- `vp run -r docgen` runs here too. An `@example` imports the package by its name, `@thomasfosterau/pulpit-wordpress` (AGENTS.md → Conventions).
